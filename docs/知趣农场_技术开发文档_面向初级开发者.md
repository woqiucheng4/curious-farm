- 假设你：会基本的 JavaScript/TypeScript 语法（变量、函数、`class`、`interface`、`async/await`），用过命令行跑 `npm install` 这类命令。

### 术语表（先扫一眼，不懂也没关系，用到时会再解释一次）

| 术语 | 大白话解释 |
|---|---|
| 场景 Scene | Three.js 里"这个世界里有什么东西"的总容器，所有能看到的物体都要添加进 Scene 里 |
| 相机 Camera | 决定"你站在哪里、往哪个方向看"，相当于玩家的眼睛 |
| 渲染器 Renderer | 把 Scene 和 Camera 的内容真正画成一张图，显示在网页的 `<canvas>` 标签里 |
| 网格 Mesh | 场景里"看得见的实体物体"，由"几何体"（形状）+"材质"（表面颜色/质感）组成 |
| 渲染循环 / 帧 | 游戏画面其实是一张张静止图片快速切换，每画一张叫"一帧"；每秒要画很多帧（比如60帧）才流畅 |
| delta time（dt） | 距离上一帧过去了多少秒；用它来计算移动速度，可以保证不同电脑帧率不同时，角色移动速度看起来一样快 |
| 射线投射 Raycasting | 从相机（或鼠标点）往场景里"发射一条看不见的激光"，判断它先打中了哪个物体，是 3D 游戏判断"点中了什么"的标准做法 |
| 状态机 State Machine | 一种编程思路：一个东西在任意时刻只能处于几种"状态"之一（比如"没在浇水" / "正在浇水"），某个事件发生时才能从一个状态切换到另一个状态 |
| 接口 interface | TypeScript 的概念，"承诺"一个类一定有哪些字段/方法，不关心具体是怎么实现的 |

## 1. 环境准备

### 1.1 需要安装的工具

- **Node.js**：建议 18 或更高版本（本文档的代码用 Node 22 验证过）。安装后在终端输入 `node -v` 能看到版本号就说明装好了。
- 不需要额外安装 Three.js 或其他依赖——项目已经把它们写进了 `package.json`，下一步 `npm install` 会自动下载。

### 1.2 把项目跑起来

```bash
cd app
npm install
npm run dev
```

`npm install` 执行完后，`npm run dev` 会启动一个本地开发服务器，终端会打印出一个网址，通常长这样：

```
  VITE vX.X.X  ready in XXX ms

  ➜  Local:   http://localhost:5173/
```

用浏览器（推荐 Chrome 或 Edge）打开这个网址。

### 1.3 你应该看到什么

一片绿色地面，中间站着一个橙色的"胶囊形状"（代表角色，后续会换成真正的人物模型），旁边有一小块棕色土壤、上面插着一个绿色圆锥（代表一株幼苗）。左上角有一个圆角小白框，写着"💧 水: 10.0"。

### 1.4 试着玩一下

- **左键点击地面空白处**：角色会走过去。
- **按住右键拖动鼠标**：镜头会绕着角色旋转。
- **左键点击幼苗**：如果角色离得远，屏幕下方会弹出"太远了，先走近一点"的提示，同时角色会自动走过去（但不会贴到幼苗正中心，会停在旁边合适的距离）。
- **走近之后，把鼠标移到幼苗上按住左键不放**：土壤颜色会慢慢变深，左上角的水量数字会持续减少。**松开鼠标**：立刻停止变化，水量不会再减少——这就是"取消"在起作用。
- 如果你一直按住到水用完（可以在下一步打开开发者工具观察，或者耐心按住几十秒），浇水会自动停止并弹出提示，不会报错也不会卡住——这就是"失败恢复"。

### 1.5 一个调试小技巧

按 `F12`（或右键"检查"）打开浏览器开发者工具，切到 Console（控制台）标签，输入：

```js
__debugGame.resourceSystem.water
```

回车就能看到当前剩余的水量数字。这是我们在 `main.ts` 里特意留的调试入口（`window.__debugGame`），开发阶段很好用，正式发布前可以考虑移除或者只在开发模式下开启。

## 3. 核心代码逐段讲解

### 3.1 `core/SceneManager.ts`：搭建舞台

```ts
this.scene = new THREE.Scene();
this.camera = new THREE.PerspectiveCamera(60, window.innerWidth / window.innerHeight, 0.1, 1000);
this.renderer = new THREE.WebGLRenderer({ antialias: true });
```

这三行是几乎所有 Three.js 项目的标配：
- `Scene`：场景容器。
- `PerspectiveCamera`：带透视效果的相机（近大远小，符合人眼直觉），四个参数依次是"视野角度 FOV"、"宽高比"、"近裁剪面"、"远裁剪面"（太近或太远的东西不会被画出来，是为了省性能）。
- `WebGLRenderer`：真正干活的渲染器，`antialias: true` 是开启抗锯齿，让边缘不那么"锯齿状"。

接下来两行加光：

```ts
const ambientLight = new THREE.AmbientLight(0xffffff, 0.6);
const sunLight = new THREE.DirectionalLight(0xfff2cc, 1.2);
```

**新手常见坑**：Three.js 里如果场景没有光源，所有物体都会是全黑的，即使材质设置了颜色。`AmbientLight`（环境光）给所有物体一个均匀的基础亮度，`DirectionalLight`（平行光，模拟太阳）会产生方向性的明暗和阴影效果。两者搭配使用效果更自然。

地面是这样做的：

```ts
const groundGeometry = new THREE.PlaneGeometry(40, 40);
this.ground.rotation.x = -Math.PI / 2;
```

`PlaneGeometry` 默认是竖直的（像一面墙），所以要绕 X 轴转 -90 度（`-Math.PI / 2`，Three.js 的角度单位是弧度不是角度，180度=`Math.PI`）让它"躺平"变成地面。

最后，渲染循环：

```ts
start() {
  const loop = () => {
    const dt = this.clock.getDelta();
    for (const cb of this.updateCallbacks) cb(dt);
    this.renderer.render(this.scene, this.camera);
    requestAnimationFrame(loop);
  };
  requestAnimationFrame(loop);
}
```

`requestAnimationFrame` 是浏览器提供的 API，意思是"在下一次屏幕刷新之前，调用我这个函数"——这是浏览器里做动画/游戏循环的标准写法，比用 `setInterval` 更流畅、更省电。每一帧，我们先执行所有"注册过的更新函数"（比如角色移动、浇水进度），再调用 `renderer.render` 把最新状态画出来。

`onUpdate(callback)` 这个方法就是让其他模块（比如 `PlayerController`）能够"插入"自己的每帧逻辑，不需要修改 `SceneManager` 本身的代码。

### 3.2 `core/PlayerController.ts`：点击移动是怎么实现的

先看移动逻辑（在 `update(dt)` 方法里）：

```ts
const direction = new THREE.Vector3(
  this.moveTarget.x - current.x,
  0,
  this.moveTarget.z - current.z
);
const distance = direction.length();

if (distance <= this.arriveThreshold) {
  this.moveTarget = null;
} else {
  direction.normalize();
  const step = Math.min(this.moveSpeed * dt, distance);
  current.x += direction.x * step;
  current.z += direction.z * step;
}
```

逐行解释：
1. 算出"从当前位置到目标点"的方向向量（`y` 设成 0，因为我们不处理上下移动，地形先按平地设计）。
2. `direction.length()` 算出还有多远。
3. 如果已经很近了（小于 `arriveThreshold`，当前是0.1），就直接停下来，`moveTarget = null`。
4. 否则，`normalize()` 把方向向量变成"长度为1的单位向量"（只保留方向，不保留距离），再乘以"这一帧应该走多远"（`moveSpeed * dt`，但不能超过剩余距离，否则会"冲过头"再弹回来）。

**为什么要乘 `dt`？** 如果不乘 `dt`，直接写 `current.x += direction.x * 某个固定数`，那么游戏在60帧/秒的电脑上角色会比在30帧/秒的电脑上快一倍——因为前者每秒执行这段代码的次数是后者的两倍。乘上 `dt`（这一帧经过的秒数）之后，"每秒移动 `moveSpeed` 个单位"这件事就和帧率无关了，这是游戏开发里非常基础、也非常重要的一个习惯，以后写任何"随时间变化"的逻辑都要记得考虑 dt。

再看镜头旋转部分：

```ts
private yaw = 0;
private pitch = 0.5;
```

这是用"球坐标"的思路实现"镜头绕角色旋转"：想象角色站在一个球的中心，相机永远贴着球面站着，`yaw`（水平角）决定相机在球面上绕"竖直轴"转到了什么角度，`pitch`（俯仰角）决定相机是从上往下看还是从侧面平视。`updateCameraPosition()` 方法就是把这两个角度换算成相机的实际 x/y/z 坐标：

```ts
const horizontalDistance = this.cameraDistance * Math.cos(this.pitch);
const verticalDistance = this.cameraDistance * Math.sin(this.pitch);
camera.position.set(
  target.x + horizontalDistance * Math.sin(this.yaw),
  target.y + verticalDistance + 1,
  target.z + horizontalDistance * Math.cos(this.yaw)
);
```

这里用到了三角函数（`sin`/`cos`），如果你对这部分数学不熟悉，没关系——这是"球坐标转直角坐标"的标准公式，记住"这段代码的作用是什么"就够了，不需要每次都重新推导。

最后是拖拽事件：

```ts
dom.addEventListener('pointerdown', (e) => {
  if (e.button === 2) { this.isDraggingCamera = true; ... }
});
```

`e.button === 2` 表示鼠标右键（0是左键，1是中键，2是右键）。`pointerdown`/`pointermove`/`pointerup` 是浏览器统一处理鼠标和触屏点击的事件（比分别处理 `mousedown` 和 `touchstart` 更省事）。

### 3.3 `interaction/Interactable.ts`：为什么要定义一个"接口"

```ts
export interface Interactable {
  object3D: THREE.Object3D;
  interactionRange: number;
  onInteract(): void;
  onInteractEnd?(): void;
}
```

这是整个项目里最重要的一个设计决定，一定要理解：**`InteractionManager`（负责处理点击）完全不需要知道"这个物体到底是幼苗还是水壶还是小鸡"**，它只需要知道"这是一个 `Interactable`，我可以读它的 `object3D` 和 `interactionRange`，可以调用它的 `onInteract()`"。

这样做的好处：以后你新增"拿取水壶"、"喂食鸡舍"等功能时，只需要写一个新的类去实现这个接口，**完全不需要修改 `InteractionManager.ts` 一行代码**。这是面向对象编程里一个很常见也很有用的思路，叫"面向接口编程"。

`onInteractEnd?()` 后面的问号表示这是"可选"的——不是所有可交互物体都需要"松开时做点什么"（比如"拿取"可能一次点击就完成了，不需要处理松开）。

### 3.4 `interaction/InteractionManager.ts`：点击到底是"移动"还是"交互"

核心逻辑在 `onPointerDown` 里：

```ts
const hitInteractable = this.raycastInteractables();
if (hitInteractable) {
  this.tryInteract(hitInteractable);
  return;
}
const groundHit = this.raycaster.intersectObject(this.sceneManager.ground)[0];
if (groundHit) {
  this.playerController.setMoveTarget(groundHit.point);
}
```

先判断这次点击有没有"打中"某个可交互物体；如果打中了，走交互逻辑，`return` 直接结束（不会再去判断地面）；如果没打中任何可交互物体，再去判断是不是点在了地面上，是的话就移动过去。

`raycastInteractables()` 怎么判断"打中了谁"：

```ts
const objects = this.interactables.map((i) => i.object3D);
const hits = this.raycaster.intersectObjects(objects, true);
```

`intersectObjects` 的第二个参数 `true` 表示"递归检查子物体"——因为 `Sprout` 的 `object3D` 其实是一个 `Group`（组），里面装着土壤、植株、水滴三个子物体，射线实际打中的是某个子 Mesh，而不是最外层的 Group。所以打中之后还需要"往上找父节点"，确认它属于哪个注册过的 `Interactable`：

```ts
private isDescendantOf(node: THREE.Object3D, ancestor: THREE.Object3D): boolean {
  let current: THREE.Object3D | null = node;
  while (current) {
    if (current === ancestor) return true;
    current = current.parent;
  }
  return false;
}
```

这是一个很常见的"顺着父子关系往上找"的写法，`current.parent` 就是 Three.js 里每个物体都自带的"我的上一级是谁"的引用。

`tryInteract` 里判断"够不到"的情况：

```ts
const inRange = this.playerController.isWithinRange(
  interactable.object3D.position,
  interactable.interactionRange
);
if (!inRange) {
  this.onFeedback('太远了，先走近一点');
  const approachPoint = this.computeApproachPoint(...);
  this.playerController.setMoveTarget(approachPoint);
  return;
}
```

**一个容易忽略但很重要的细节**：`computeApproachPoint` 不是简单地把移动目标设成"物体的正中心"，而是在"物体到玩家当前位置"的连线上，找一个距离物体 `interactionRange` 稍近一点的点。如果直接把目标设成物体中心，角色会一路走到完全重叠在幼苗上面，看起来很奇怪。这个函数我在写的时候一开始没加，测试的时候发现了这个问题才补上——**这是一个真实的"踩坑再修复"的例子**，你自己写类似逻辑时也要注意这一点。

### 3.5 `economy/ResourceSystem.ts`：资源怎么安全地加减

```ts
trySpendWater(amount: number): boolean {
  if (this._water < amount) return false;
  this._water -= amount;
  this.notify();
  return true;
}
```

注意方法名是 `trySpend` 而不是直接 `spend`——这是一个命名习惯：**返回 `boolean` 的方法名最好能让人一看就知道"这个操作可能会失败"**。调用方（`Sprout.ts`）必须检查返回值，不能假设扣减一定成功：

```ts
const spent = this.resourceSystem.trySpendWater(waterNeeded);
if (!spent) {
  // 处理"水不够"的情况
}
```

**这是对应产品设计里"浇水落空不能扣水"这条规则的关键位置**：`ResourceSystem` 自己并不知道"这次浇水有没有命中有效区域"，它只负责"如果你要花这么多水，告诉我，我要么真的扣掉、要么告诉你钱不够"。真正"该不该扣"的判断，必须由调用方（`Sprout.ts` 的 `update` 方法）在**确认命中有效区域之后**才去调用 `trySpendWater`。如果你以后新增别的消耗资源的动作，一定要记住这个原则：**不要在"还不确定这次操作是否有效"的时候就先扣资源**。

订阅者模式部分：

```ts
subscribe(listener: () => void): () => void {
  this.listeners.push(listener);
  return () => { this.listeners = this.listeners.filter((l) => l !== listener); };
}
```

如果这段代码你一下子看不懂也没关系：可以先这样理解——"谁想在资源变化时收到通知，就把自己的回调函数塞进来；`ResourceSystem` 数值一变，就把列表里所有回调函数都执行一遍"。`HUD.ts` 就是这样用的：

```ts
resourceSystem.subscribe(() => this.updateWaterLabel());
```

如果你暂时觉得这个模式太绕，一个更简单但不够优雅的替代方案是：让 HUD 在每一帧都主动去读一次 `resourceSystem.water` 并刷新界面，不等通知。两种做法效果一样，订阅模式只是"性能更好、代码更解耦"，不是必须的，等你写顺手了再用也不迟。

### 3.6 `world/Sprout.ts`：完整的"五要素"范例（最重要的一节）

这是整个项目里**最值得反复看的一个文件**，因为设计文档要求"拿取/浇水/喂食/收获"每一个都要有完整的"输入→过程→反馈→取消→失败恢复"，`Sprout.ts` 就是浇水这一个动作的完整实现，之后你写其他三个动作时应该照着这个结构抄。

**输入**对应 `onInteract()`：

```ts
onInteract() {
  if (this.wetness >= 1) {
    this.onFeedback('这株苗已经浇够水了');
    return;
  }
  if (this.resourceSystem.water <= 0) {
    this.onFeedback('水壶没水了，先去获取一些水吧');
    return;
  }
  this.isPouring = true;
  this.waterDropMesh.visible = true;
}
```

注意这里有两个"提前返回"（early return）的判断：已经浇够了、或者没水了，都不会真的开始"倒水"状态。这是把"失败恢复"的一部分提前处理掉了——压根不让一个注定会失败的动作开始，比开始了之后再处理失败更简单。

**过程**对应 `update(dt)` 里 `if (!this.isPouring) return;` 之后的部分，每一帧都在做三件事：①尝试扣水 ②如果扣水成功就增加湿润度、改变土壤颜色 ③检查是不是已经浇满了。

**反馈**是土壤颜色变化（`material.color.lerpColors(...)`，`lerpColors` 是"线性插值"，按 `wetness`（0到1之间）这个比例，在"干燥色"和"湿润色"之间算出一个中间色）和水滴的上下浮动动画（`Math.sin(performance.now() / 150) * 0.05`，用正弦函数做一个简单的周期性浮动效果，这是做"呼吸感"小动画最常用的技巧之一）。

**取消**对应 `onInteractEnd()`：

```ts
onInteractEnd() {
  this.isPouring = false;
  this.waterDropMesh.visible = false;
}
```

就这么简单——松开鼠标，立刻把 `isPouring` 设成 `false`，下一帧 `update` 的 `if (!this.isPouring) return;` 就会直接跳过，不会再扣任何水、不会再有任何变化。**没有额外的"惩罚"逻辑，这是故意的**，对应产品设计里"取消不应该产生任何后果"的要求。

**失败恢复**对应 `update` 里的这一段：

```ts
const spent = this.resourceSystem.trySpendWater(waterNeeded);
if (!spent) {
  this.isPouring = false;
  this.waterDropMesh.visible = false;
  this.onFeedback('水壶没水了，先去获取一些水吧');
  return;
}
```

水在倒的过程中突然用完了，游戏不会报错、不会卡住，而是优雅地自动停止并提示，就像玩家自己松开了鼠标一样。

## 4. 动手练习 1：实现"拿取"动作

现在轮到你了。目标：做一个可以被"拿起来"的水壶道具。

### 4.1 先想清楚状态

参考 `Sprout.ts` 的结构，拿取动作需要：
- 一个布尔值 `isHeld`（表示现在是不是已经被拿在手上）。
- `onInteract()`：如果 `!isHeld`，播放"拿起"的效果，把 `isHeld` 设为 `true`；如果已经 `isHeld`，可以让同一次点击变成"放下"（这是一种简单的拿取+放下二合一设计，比严格照搬产品文档"再次点击单独放下"更容易实现，作为练习先这样做也可以）。

### 4.2 参考代码框架

新建 `src/world/WateringCan.ts`：

```ts
import * as THREE from 'three';
import type { Interactable } from '../interaction/Interactable';

export class WateringCan implements Interactable {
  object3D: THREE.Group;
  interactionRange = 1.5;

  private isHeld = false;
  private readonly groundPosition: THREE.Vector3;

  onFeedback: (message: string) => void = () => {};

  constructor(position: THREE.Vector3) {
    this.groundPosition = position.clone();
    this.object3D = new THREE.Group();
    this.object3D.position.copy(position);

    // 用一个简单的圆柱体代表水壶，后续可以换成更精细的模型
    const geometry = new THREE.CylinderGeometry(0.15, 0.2, 0.4, 12);
    const material = new THREE.MeshStandardMaterial({ color: 0x5577aa });
    const canMesh = new THREE.Mesh(geometry, material);
    canMesh.position.y = 0.2;
    this.object3D.add(canMesh);
  }

  onInteract() {
    if (this.isHeld) {
      // 第二次点击：放下，回到原来的位置
      this.isHeld = false;
      this.object3D.position.copy(this.groundPosition);
      this.onFeedback('放下了水壶');
    } else {
      // 第一次点击：拿起
      this.isHeld = true;
      this.onFeedback('拿起了水壶');
      // TODO: 这里只是把水壶"标记为拿起"，还没有真的让它跟着角色的手部位置走。
      // 练习：试着让水壶每一帧都跟随角色的位置（可以参考 PlayerController 暴露的 mesh.position，
      // 把水壶的 position 设置成角色位置 + 一个偏移量，比如往前和往右各偏移一点）。
    }
  }

  getIsHeld() {
    return this.isHeld;
  }
}
```

**这个练习留了一个 TODO 故意不写完**：如何让水壶"跟着角色的手"移动。提示：你需要在 `SceneManager.onUpdate` 里注册一个每帧执行的函数，在这个函数里把 `wateringCan.object3D.position` 设置成 `playerController.mesh.position` 加上一个偏移向量。可以参考 `PlayerController.ts` 里 `mesh.rotation.y` 的写法，让偏移方向也跟着角色的朝向转动（这样水壶才会一直"举在角色前方"而不是固定在世界的某个方向）——这部分稍微有点难度，如果一开始做不出来，可以先让水壶简单地"悬浮在角色头顶上方"，能跑起来比完美更重要，后面再优化。

### 4.3 别忘了注册

在 `main.ts` 里新增水壶实例、注册进 `interactionManager`，和 `Sprout` 的写法一样：

```ts
const can = new WateringCan(new THREE.Vector3(-1.5, 0, 1));
can.onFeedback = (message) => hud.showFeedback(message);
sceneManager.scene.add(can.object3D);
interactionManager.register(can);
```

## 5. 动手练习 2：实现"收获"动作

目标：给 `Sprout`（或者新建一个 `Carrot.ts`）加上"长大之后可以被采摘"的逻辑。

### 5.1 关键设计点

- 需要一个 `isHarvestable(): boolean` 方法——只有幼苗"浇够水"（`wetness >= 1`，可以直接复用 `Sprout.ts` 里已经有的 `getWetness()`）之后才允许采摘。
- `onInteract()` 里先检查 `isHarvestable()`：
  - 如果**不满足**：不要直接报错或者弹出"任务失败"，而是给一个温和的提示，比如"还没长好，再等等"，这对应产品设计里"未成熟果实拒绝被摘、不计入失败"的要求。
  - 如果**满足**：播放"采摘"效果（比如让植株的 Mesh 缩小消失，或者直接从场景里移除），调用资源系统增加一点"农场币"或者触发收获计数。

### 5.2 参考代码片段（加在 `Sprout.ts` 里，或者单独抽成一个 `isHarvestable` 判断逻辑复用）

```ts
isHarvestable(): boolean {
  return this.wetness >= 1;
}

harvest(): boolean {
  if (!this.isHarvestable()) {
    this.onFeedback('还没长好，再等等');
    return false;
  }
  // 采摘成功：这里先简单处理成"从场景里消失"，表示已经被收走
  this.object3D.visible = false;
  this.onFeedback('收获成功！');
  return true;
}
```

注意 `harvest()` 返回了一个 `boolean`——这是在提醒调用方"这个操作可能失败"，和 `ResourceSystem.trySpendWater` 是同样的命名习惯，建议你在整个项目里都保持这种一致性，这样代码读起来更容易预测行为。

**练习**：想一想，如果这是一个"只能摘成熟番茄、摘到青色算错"的任务（对应产品文档第6节的语文例题），应该怎么设计"摘错了允许放回"的逻辑？提示：可以在"篮子"这个 UI 组件里维护一个"已放入篮子的物品列表"，每个物品旁边加一个"放回"按钮，点击后把对应物品从列表里移除、把对应的植株 `visible` 重新设为 `true`。这个练习会用到一点列表（数组）的增删操作，是检验你是否已经掌握前面知识的一个好机会。

## 6. 动手练习 3（进阶）：实现"喂食"与确认分配面板

这是四个动作里最复杂的一个，因为产品文档要求"倾倒是连续动作，但最终的份数分配需要有一个确认/调整的环节"。建议按这几步来：

1. 先写一个最简单的版本：点击食槽一次 = 增加一份，不做"确认面板"，验证基本的"份数累加、资源扣减"逻辑能跑通。
2. 再加一个简单的 HTML 面板（参考 `HUD.ts` 创建 DOM 元素的写法），在"倾倒若干次"之后弹出，列出当前每个食槽的份数，提供"确认"和"取消"两个按钮。
3. **关键原则**：份数的累加只存在组件内部的一个临时变量里（比如 `pendingAmounts: Record<string, number>`），**只有点击"确认"之后，才真正调用 `ResourceSystem` 扣减资源**；点击"取消"，这个临时变量直接丢弃，不产生任何效果。这是在代码层面落实"操作失误不计入知识判断"的关键——因为只要玩家还没点"确认"，之前的操作都可以无代价地重来。

这部分代码框架较复杂，建议你先完成练习1和练习2、确认自己已经熟悉"状态机+资源系统"的配合方式之后再做这一部分。如果卡住了，可以参照 `Sprout.ts` 的结构（私有状态变量 + `onInteract`/`onInteractEnd`/`update` 三个方法的分工）来组织代码，思路是一致的，只是多了一个"UI确认"的环节。

## 7. 存档系统（里程碑A后期再做）

项目已经安装了 `idb-keyval`（一个对 IndexedDB 的简单封装，比直接用浏览器原生的 IndexedDB API 好写得多）。一个最简单的存读档示例：

```ts
import { get, set } from 'idb-keyval';

interface SaveData {
  version: number;
  water: number;
}

async function saveGame(resourceSystem: ResourceSystem) {
  const data: SaveData = { version: 1, water: resourceSystem.water };
  await set('knowing-farm-save', data);
}

async function loadGame(): Promise<SaveData | undefined> {
  return get('knowing-farm-save');
}
```

**练习**：在 `main.ts` 里，游戏启动时调用 `loadGame()`，如果读到了存档就用存档里的水量初始化 `ResourceSystem`（你可能需要给 `ResourceSystem` 加一个 `setWater(amount)` 方法）；再找一个合适的时机（比如每次浇水完成时）调用 `saveGame(resourceSystem)`。`get`/`set` 都是 `async` 函数（返回 Promise），记得用 `await` 或者 `.then()` 处理。

## 9. 常见问题 / 踩坑提示

以下几条是我在搭建这个起步项目时**真实遇到过**的错误，记录下来避免你重复踩坑：

**Q: 运行 `npm run build` 报错 `This syntax is not allowed when 'erasableSyntaxOnly' is enabled`，指向类似 `constructor(private xxx: Xxx)` 这样的代码？**

A: 项目的 `tsconfig.json` 开启了 `erasableSyntaxOnly`，这个选项不允许用"构造函数参数属性简写"（就是 `constructor(private foo: Foo)` 这种直接在构造函数参数前面写 `private` 来自动创建同名字段的写法）。解决办法：改成老老实实的两步写法：

```ts
// 不要这样写：
constructor(private foo: Foo) {}

// 要这样写：
private foo: Foo;
constructor(foo: Foo) {
  this.foo = foo;
}
```

本项目里 `PlayerController`、`InteractionManager`、`HUD`、`Sprout` 都是用的后一种写法，照着抄就行。

**Q: 报错 `'Xxx' is a type and must be imported using a type-only import when 'verbatimModuleSyntax' is enabled`？**

A: 如果你 `import` 的东西只是一个 TypeScript 的 `interface`（比如 `Interactable`），在运行时根本不存在、只是给类型检查用的，就要写成：

```ts
import type { Interactable } from '../interaction/Interactable';
```

而不是普通的 `import { Interactable } from ...`。简单的判断方法：如果这个东西是用 `interface` 定义的，大概率要用 `import type`；如果是用 `class` 定义的（运行时真实存在），用普通 `import` 就行。

**Q: 画面全黑，什么都看不见？**

A: 最常见的原因是忘记加光源（见第3.1节），或者相机位置、朝向不对（比如相机和物体位置重合，或者相机背对着场景）。可以先在控制台打印 `camera.position` 和你想看的物体的 `position`，确认两者之间有一段合理的距离。

**Q: 点击没反应，既不移动也不触发交互？**

A: 先确认你点击的 DOM 元素是不是被其他元素"挡住"了——比如 `HUD.ts` 里专门把 `.hud` 这个容器设置了 `pointer-events: none`（见 `style.css`），就是为了让鼠标事件能"穿透"HUD 落到下面的 3D 画面上；如果你新增的 UI 元素忘了加这个属性，可能会挡住本该发给 Three.js 画面的点击事件。

**Q: `npm run build` 提示 "Some chunks are larger than 500 kB"？**

A: 这只是一个警告，不是错误，构建仍然成功。Three.js 库本身体积比较大，这在 3D 网页项目里很常见，里程碑A阶段不需要处理这个警告，后续如果关心加载速度可以再研究"代码分割"（警告信息里提到的 `dynamic import()`）。
